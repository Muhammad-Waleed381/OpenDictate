# Recording, settings, and model-command repairs

Scope: B001–B013, B015, B027, B033, B046, B047, B064. Files owned: `dictation.rs`, `state.rs`, `lib.rs`, new `session.rs`, and `commands.rs` strictly above `test_groq_api_key`. Parent owns native input and the remaining commands; core owns recorder, model-file exclusion, and decoder APIs.

## Verification and reproduction

Before changing the isolated action/onset policies, `cargo test -p opendictate --lib session::tests --locked` ran four substantive assertion failures: failed insertion still called Enter; clipboard-only completion still called Enter; confirmed speech omitted the first positive batch; uninterrupted speech never triggered the cap. These policies were extracted from the audited branches so tests could execute without issuing desktop input or requiring models. All four now pass and the repaired helpers are called by the actual action/handsfree paths.

`cargo test -p opendictate --lib session --locked`: **17 passed** before the final input-target integration. The worker's integration rerun `cargo test -p opendictate --lib --locked`: **54 passed, 0 failed**, including the command-payload/capture-handoff regressions, input-target regression, and parent native/DB/hotkey/legacy-settings tests. The parent's final combined workspace run included **55 app tests**, all passing. `git diff --check` passed for every owned source/report path. The two initial common-cleanup assertions incorrectly assumed `clean_text` adds a terminal period; expectations were corrected to its existing punctuation-preserving contract, rather than introducing unrelated output changes.

Other lifecycle defects were reproduced by the completed three-role source audit, then checked by focused ownership/lock-order tracing and compiled regression coverage. This report does not claim a live desktop or model-backed red/green reproduction for paths that require native audio, model inference, or OS integration. No paid API calls, model downloads, real text injection, or production data deletion were used.

## Integration changes

- B019/B020: hotword phrases remain plain newline-separated text (no invented underscore/score tokens); core validates and encodes them. Generic cleanup runs before dictionary casing restoration. Regression tests cover phrase preservation and canonical spelling.
- B023: the exact production `prepare_transcript` now invokes the case-preserving action parser on original text before any prose normalization; spoken punctuation and dictionary correction cannot mutate URL/prompt payloads. Snippet matching is ASCII-case-insensitive only for prefixes, and names/suffixes are sliced from original text without reconstruction or lowercasing. The three `prepared_*` URL, prompt, and snippet regressions failed on the previous production preparation (URL `/file.json` became `/file.JSON`, prompt punctuation words changed, snippet suffix lowercased), then passed. Additional tests cover aliases/Unicode and disabled actions; prose dictionary tests now exercise the same preparation helper.
- B008/B018 integration: `begin_explicit_capture` joins/discards a failed backend before clearing its retained audio and reconnecting. This applies only to a fresh explicit start; same-session failure finalization still retains its tail. `explicit_start_discards_failed_capture_audio_after_joining_its_producer` reproduced retained old samples before repair and passes afterward. The live-handsfree branch clears without stopping/reopening capture.
- B025: backend rejects enabling unavailable `local_slm`, including compound patches.
- B029: settings add `input_target` (`text` default, or `terminal`); dispatch passes the app handle to the parent's target-aware delete-line implementation.
- B055: single-instance `--toggle` invokes dictation without opening the main window; cold `--toggle` hides main and dispatches after setup.
- Parent's `test_snippet` is registered in the invoke handler. Public start/stop/cancel entry points remain unchanged for its ordered hotkey queue.

No files outside ownership were formatted. In particular, only the owned `commands.rs` prefix was passed through rustfmt and the current parent's suffix was preserved on each write.
